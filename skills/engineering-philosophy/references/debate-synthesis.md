# 辩论纪要与裁决(摘要):严谨 vs 速度

> 这套 skill 的结论不是拍脑袋写的,是让**五个互不通气的模型**分角色(前端 / 后端 / 前后端契约 / 红队 / 速度务实反方)辩论,再由 Opus 4.8 当裁判综合出来的。这里只留三条最硬的结论;想理解每条原则背后的取舍,读这一篇就够。

## 表面的死斗

工程师阵营(前端 / 后端 / 契约 / 红队)要你:画对数据模型、别造假连接、标注天花板、守住红线。
速度务实派当场掀桌:

> "Demo 不是软件,是**证据机器**,唯一 KPI 是用最短时间杀死一个不确定性。给注定要扔的东西建模型、写测试、搭鉴权,是**给还没断气的尸体化妆**。"

## 裁判的三条结论

**1. 这是"站位错觉",不是真分歧。**
速度派说"别建数据模型",默认的是 **Demo**;后端说"先把数据模型画对",默认的是**要变成产品的那条线**。他们站在不同阶段,各自都对。真正的错误从来不是"选严谨"或"选速度",而是**把一个阶段的正确答案用到了另一个阶段**。所以:**脱离阶段谈严谨度,全是空话。**

**2. 真正的悬崖在 POC→MVP 之间,不在 Demo→POC。**
前两段花的是"**学习成本**"(东西大概率被扔,糙、快、扔全对);越过去是"**信任成本**"(有了真实用户和真钱,持久化、隔离、安全必须一次跳到位)。所以严谨度不是平滑斜坡,是**两级台阶**——这一点是前端、后端、速度派三方各自独立撞出来的,可信。

**3. 判词:严谨度跟着阶段走,诚实度不跟阶段走。**
你可以在任何阶段把东西做得很假,但你不可以对"它有多假"这件事撒谎——尤其不能骗自己(连最激进的速度派都把"自己骗自己"列为唯一无法挽回的错)。**作弊是聚焦的艺术,自欺是最贵的错误。**
